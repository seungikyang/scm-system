# SCM 취업 포트폴리오 가이드

> [HTML 학습 목차](../index.html) · [문서 지도](./INDEX.md) · [루프 엔지니어링](./LOOP_ENGINEERING.md)

## 1. 프로젝트 한 문장

Java 17과 Spring Boot로 거래처·품목 마스터, 다단계 발주 승인·입고, 안전재고 조회를 구현하고 요구사항부터 동시성 테스트와 MySQL 마이그레이션까지 직접 설명하는 SCM 취업 워크북이다.

## 2. 이 프로젝트로 보여줄 역량

| 역량 | 증거 |
|---|---|
| 요구사항 분석 | PRD/TRD와 구현 차이를 결정표로 관리 |
| 객체지향 설계 | 발주 상태 전이를 도메인 메서드로 캡슐화 |
| 계층 분리 | Web/REST Controller가 동일 Service를 사용 |
| 데이터 정합성 | 입고 상태와 재고 증가를 하나의 트랜잭션으로 처리 |
| 동시성 대응 | 낙관적 락, 품목 잠금, 최대 번호 채번, UNIQUE·독립 트랜잭션 재시도 |
| 운영 DB | Flyway 버전 스키마, Hibernate validate, 실제 MySQL CI |
| 보안 | 세션 인증, Service 인가, CSRF와 보안 헤더 |
| 테스트 | 단위·MockMvc·H2 흐름/동시성 테스트와 MySQL 스키마 테스트 |
| 문제 해결 | OSIV, 채번, 동시 입고, 빌드 환경 트러블슈팅 |
| 학습 설계 | 40개 빈칸 모듈과 참조 구현 연결 |

## 3. 3분 데모 시나리오

1. 일반 사용자로 로그인한다.
2. 공급사와 활성 품목을 선택해 발주서를 작성한다.
3. 총금액이 클라이언트가 아니라 서버에서 계산되는 지점을 설명한다.
4. 작성자가 결재를 요청한다.
5. 관리자 또는 매니저가 승인한다.
6. 입고 처리 후 재고 화면에서 현재고와 안전재고 부족 상태를 확인한다.
7. 동시 발주·동시 최초 입고 테스트와 잘못된 상태 전이 차단을 보여준다.

## 4. 핵심 면접 질문

- 왜 발주 헤더와 라인은 하나의 aggregate로 보았나요?
- 왜 Partner, Item, User는 JPA 연관관계 대신 ID로 참조했나요?
- OSIV를 끄면 어떤 문제가 생기고 표시값을 어디에서 채우나요?
- 동시에 두 관리자가 같은 발주를 승인하면 어떻게 되나요?
- 입고 상태 변경과 재고 증가를 왜 하나의 트랜잭션으로 묶나요?
- 발주번호 `count + 1` 대신 최대 번호와 UNIQUE 재시도를 선택한 이유는 무엇인가요?
- Controller와 Service 양쪽에서 권한을 다르게 다루는 이유는 무엇인가요?
- H2와 MySQL의 동작 차이를 어떤 CI 단계로 검증하나요?
- 입고 이력이 없는 품목을 재고 화면에서 누락하지 않는 방법은 무엇인가요?

답변은 “사용 기술”보다 `문제 → 선택 → 대안 → 검증 결과` 순서로 준비한다.

## 5. 이력서 문장 만들기

아래 문장은 그대로 복사하기보다 수치와 자신의 판단을 채운다.

```text
- Java 17/Spring Boot 기반 SCM에서 발주 작성부터 승인·입고까지 6개 상태의 전이를 도메인 규칙으로 구현했습니다.
- 입고와 재고 증가를 단일 트랜잭션으로 묶고, 낙관적 락과 품목 잠금으로 동시 처리 시 정합성을 보호했습니다.
- 입고 이력이 없는 품목도 0 재고로 조회하도록 Item-Stock LEFT JOIN을 설계하고, 부족수량과 안전재고 상태를 REST·Thymeleaf에 동일하게 제공했습니다.
- Flyway와 Hibernate validate로 MySQL 스키마 변경 책임을 분리하고, 기본 93개 + MySQL 전용 1개 테스트 계약으로 핵심 규칙을 검증했습니다.
- PRD와 실제 구현의 정책 차이를 상태표와 설계 결정 문서로 관리하고, 40개 모듈의 자력 학습 워크북으로 재구성했습니다.
```

## 7. 제출 전 체크리스트

- [ ] 저장소 첫 화면에서 프로젝트 목적과 실행 방법을 바로 이해할 수 있다.
- [ ] `index.html`에서 학습 자료와 구현 증거에 접근할 수 있다.
- [ ] 전체 테스트와 실행 가능한 JAR 빌드가 성공한다.
- [ ] 시드 계정과 비밀정보가 운영 기본값에 노출되지 않는다.
- [ ] 구현되지 않은 수주·공지를 구현된 것처럼 설명하지 않는다.
- [ ] 핵심 발주 흐름을 3분 안에 시연할 수 있다.
- [ ] 동시성·트랜잭션·보안 질문에 코드와 테스트를 근거로 답할 수 있다.
- [ ] 가장 어려웠던 문제 하나를 원인·시도·해결·검증 순서로 설명할 수 있다.
